How to use it.

Read the briefs, browse the facts, keep them fresh.

Read

  1. Start with the briefsThe reviewed synthesis — how the company makes money, the Discover deal, the credit cycle. Tap any source tag to jump to the original filing.
  2. Then the dataData holds every governed number as a series, every dated event, the entity map, and all 1,300+ documents — each row linking to its public source.
  3. The schema is the contractSchema shows what every record must carry. CI rejects anything that breaks it.

Keep it fresh

  1. Run an update when Freshness says soOne button on Update. SEC, FDIC, CFPB, and Fed data fetch themselves; validation runs before anything publishes.
  2. Upload what can't be fetchedEarnings transcripts (paywalled) and FFIEC ZIPs (download-blocked). Pick the type, fill two fields.
  3. Review drafts before they countNew machine-written briefs land on the draft/model-content git branch. Merge what passes your read — nothing counts until you do.

From the terminal

uv run factpack ask "…"        # grounded Q&A with citations (CLI + API only)
uv run factpack search "…"     # raw retrieval
uv run factpack metrics "…"    # query the number store
uv run factpack cost           # metered model spend
make fetch extract validate compile   # the update, by hand

Downstream tools consume all merged briefs from one URL: export/briefs.json on the repo's main branch.
